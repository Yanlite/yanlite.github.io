## 已确认的方向

- 保留 Astro，使用 GitHub Pages 静态部署；文章入口从 /blog 改为 /article，详情为 /article/<现有 id>，界面显示“文章”。网站尚未上线，不保留旧 /blog 地址兼容。
- Tag 机制改为统一分类机制。分类支持父子层级、文章多归属；侧栏用列表式分类导航，不再堆砌标签按钮。
- 文章填写的分类顺序决定卡片展示，最多显示两个；完整归属参与检索和统计。父分类汇总后代文章并去重。
- 原首页与 About 内容按站点与作者整合：`/about` 为关于本站，作者信息链接到 `/about/yanlite`；具体保留/删除项执行时由用户确认。首页临时展示文章列表。
- 替换模板作者个人资料、界面中文化、删除冗余功能（例如赞助）。
- 隐藏 Docs、Links、Projects，站内搜索不能搜到这些界面的内容。
- 以当前主题为起点，必要组件按需本地接管；全面脱离主题包尚未确认。

## 规划边界

只提前确定影响整体链路的范围、依赖与共同原则。具体字段、目录、URL 兼容、页面隐藏方式、About 模块及删除清单留到相应任务再解释、设计和复核；不以这些细节阻塞规划。

用户提出的首版目标包括部署上线。07 先完成可审阅改动和验证，再依据届时已有授权执行发布，不把选择平台等同于立即推送授权。

## 后续需求，不阻塞首版

- 多语言：未来预计中英日，希望即时切换；具体语言 URL、缺译和加载机制未确定。
- 完整阅读布局调整、个性化设置浮层、搜索浮层与悬浮预览。
- 专栏：文章可加入多个专栏，各专栏独立排序，集中维护有序成员；首版不提前实现。
- 结构化文章关系、拓扑排序、关系图与探索型首页。当前关联阅读可在正文手写链接。

## 如何开始

先读 [项目规则](../../AGENTS.md) 和 [00 交接](00-shared-design.md)，再读目标任务。每次只推进当前小步，持续讲解原主题与修改入口，并更新交接。

可复制开场：

在当前项目仓库中完成 docs/planning/NN-任务名.md。先读仓库根目录 AGENTS.md、总览及前置任务交接，核对现场。遵守结对讲解、过程同步和重要基层代码复核规则。只做本任务，先说明必要澄清与第一个小步；具体细节按需确定。
