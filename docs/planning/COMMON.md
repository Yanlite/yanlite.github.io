# 任务公共协作约定

适用于本目录全部首版任务。先读 [项目 AGENTS.md](../../AGENTS.md)、[总览](README.md) 和前置任务交接；现场源码与 Git 状态须重新核对，本文不是运行状态保证。

## 用户原始工作规则

在推进项目的同时让我跟进项目状态。

1. 让我了解原有主题的项目结构，让我在必要时可以手动进行修改的程度。
2. 对于重要的基层代码，我需要进行复核。
3. 每个功能实现前，简要列出功能的实现逻辑，以供检查或学习。
4. 对于跟进过程中出现我可能不懂的概念、代码语法，先进行讲解，再跟进。
5. 根据我的疑问实时更新我的知识边界和认知水平，据此执行第四条。

完成网站与积累项目、前端、Agent 协作经验是同时成立的目标，功能完成不能替代过程讲解。

## 项目协作入口

遵守项目 AGENTS.md：新概念先介绍概念和必要语法，再联系当前代码与操作；每小步只讲当前改动所需知识，不连续扩展成课程。个人学习反馈、笔记和抽认卡信息另存本地，不写入共享交接；具体个人约定如存在，另行读取，不作为项目在其他环境工作时的必要依赖。

## 每个小步

- 核对分支、未提交改动与依赖交接，说明当前状态及小步在整体中的位置。
- 先对照原主题解释数据、组件与页面调用链，再说明实现逻辑、文件、验证方法；区分原有、接管和新增内容。
- 关键发现、方案变化和阶段完成时同步状态，不能只在最终汇报。
- 重要基层代码提前提供设计；修改后给出具体差异和解释，在依赖它继续开发前留出复核点。
- 只澄清当前必须确定的内容；不影响整体链路的细节在实际任务中讨论。不能为省略复核而提前堆叠代码。
- 回应用户疑问后调整讲解深度。区分“已介绍”“用户确认理解”“仍有疑问”，不要求机械测验。
- 交付说明改动、原因、验证范围和手动维护入口；项目功能状态与个人学习进度分别交接。

## 技术与协作边界

- 提交项目 AGENTS.md 和 docs/planning/，个人学习笔记和本机记录由 /docs/learning/、/docs/local/ 规则排除；不强制添加。网站正文目录 src/content/docs/ 不受该规则影响。
- Astro + Astro Theme Pure，静态部署 GitHub Pages。不自动升级主题，不从备份恢复旧实现。
- 初始调查分支为 restart/from-initial，HEAD 为 808ce76。重新进入时核对，不改用旧 main。
- 初始配置、资料、头像及文章迁移已包含在 4c3dc30；开始时现场核对，不覆盖用户设置或混淆改动归属。
- astro-pure 导入使用安装包；packages/pure 不会自动生效。禁止直接修改 node_modules；需要改主题组件时先解释依赖与维护边界，再按需接管，不整包复制。
- 主题包同时承担组件、内容工具、虚拟配置、MDX/UnoCSS/站点地图接入、Pagefind 索引生成。不能把删除主题包当作只替换界面组件。
- 当前以 npm 开发，只有 Bun 锁文件，尚无本轮 npm 锁文件。07 必须落实锁文件与干净环境复现，之前不宣称已有 CI 保证。
- 默认顺序使用当前 checkout；若将来明确要求并行，先建立共同基线与独立工作目录，不能同时修改共享文件。
- 不自动提交、推送、强推、重置或上线；执行用户已明确授权的动作，保留备份。
- 个人资料与代码来源署名分开处理；复用源码保留适用的来源和许可信息。

## 验证

用户测试的生产预览统一为 http://127.0.0.1:4322/，启动命令 `npm run preview -- --host 127.0.0.1 --port 4322`；开发服务为 http://127.0.0.1:4321/，两者须区分。每次先核对服务状态；若预览自动改到其他端口，先排查 4322 的占用，不将其他端口当成新的测试入口。预览提供 dist/ 构建产物，源码改动需重新构建后才反映在此。

代码改动至少运行 npm run build；界面与交互改动验证生产预览。不得用 HTTP 200、脚本存在或构建成功替代浏览器交互验证。文档改动检查链接、任务依赖和决策一致性即可。

记录未执行的检查、现存提示与环境限制；不为绕过沙箱权限问题修改业务代码。

## 每份任务的交接格式

- 状态、已完成、待办。
- 已确认决策与仍需复核项。
- 修改文件、可供后续使用的接口。
- 验证结果与未覆盖事项。
- 与代码有关的设计理由、未解问题与复核点。
- 个人学习反馈、笔记位置与卡片 ID 留在本地交接，不纳入共享项目记录。
- 手动修改入口和下一小步。

未开始的任务不填写虚构成果；任务依赖调整同步总览。
