# 07 整体验收与 GitHub Pages 部署

状态：待开始。前置：01–06 的实际交接。

先读 [总览](README.md)、[公共约定](COMMON.md)、[00 交接](00-shared-design.md) 及前置任务的实际交接。先核对现场，再说明第一个小步；以下入口仅供调查，不是任意改写的清单。

## 目标与范围

完成首版整体检查，建立可复现构建与 GitHub Pages 部署流程，并按有效授权初步上线。

## 分步推进

1. 核对分支、改动归属与各任务记录，形成明确发布范围，不混入延期功能。
2. 核对包管理器和依赖，落实锁文件及干净环境安装；不要依赖旧 node_modules 或自动升级主题。向用户解释安装、检查、构建、部署的输入输出。
3. 准备可复核的 GitHub Actions 工作流，验证 Linux 构建、静态资源、图片与 Pagefind 索引。
4. 整体验证文章入口/首页、分类列表、About、个人资料与中文化、隐藏页面和真实搜索；核对 RSS、站点地图、canonical、404、旧路径与移动端。
5. 上线前确定评论启用或关闭。现有 Waline 是示例服务，启用需用户自己的服务和数据库；不将 GitHub Pages 与评论服务混为一体。
6. 完成改动、解释和验证后，依据已有授权执行提交/推送/发布；若缺少必要授权，在可审阅结果准备好后询问。
7. 验证正式网址与搜索等关键功能，记录回退与手动维护方式。

## 主要入口

package.json、锁文件、.github/workflows/、astro.config.ts、src/site.config.ts、构建产物与发布平台设置。

## 执行时才确定

仓库与发布分支、平台权限、评论、最终发布时机。正式 site 当前为 https://yanlite.github.io，若仓库或域名条件变化须重新核对。

## 验收

- 干净环境可安装、Linux 构建通过，工作流经复核。
- 首版各任务验收有依据，区分构建、浏览器与线上验证。
- 按授权上线后验证实际网址、资源、404、搜索与适用的评论，并记录回退办法。

## 边界

不强推、不覆盖旧 main、不删除备份。多语言、专栏、浮层、关系图及探索型首页不阻塞本次发布。
